nx_array — релизный комплект 2026-11-11

Варианты:
- nx_array_qt.h — Qt; проверен с Qt 5.14.2, MinGW 7.3, C++11.
- nx_array_vc.h — универсальный заголовок для Visual C++ и других
  C++11-компиляторов; не требует Qt.
- nx_array_cb.h — C++Builder 10 с Clang-компилятором, Win32/Win64.
Выберите один вариант: заголовки определяют один класс nx_array и имеют
общий include guard. Не включайте разные варианты в одну единицу трансляции.

Последние исправления
Все варианты защищают копирующие преобразования const-временных владельцев
сырых указателей. Общие методы: toStdList, toStdArray, toStdVector,
toStdDeque; в Qt дополнительно toQList. Небезопасный вызов отвергается
std::invalid_argument. Проверяются также явные шаблонные аргументы.
Безопасное копирование у живого lvalue и перемещение non-const источника
сохранены. START_POS/END_POS получили определения для использования
по ссылке/адресу в нескольких .cpp в C++11.

Контракт владения
isDeleteItemsOnDestroy по умолчанию false. Копии сырых указателей не
продлевают жизнь объектов. Копия владельца является невладеющим массивом;
она не должна переживать исходного владельца. Присваивание заменяет
указатели, не удаляя прежние объекты; при необходимости вызывайте
clear_with_delete() явно. Не передавайте один объект двум владельцам.
Операторы << могут перемещать из неконстантного lvalue; это не семантика
QList. nx_array не является совместимой заменой всего QList API.

Стабильность
Объекты находятся в узлах std::list, индекс — в std::vector указателей.
Рост сохраняет адреса существующих объектов, но не исключает выделений
памяти. Итераторы позиционные и не обязаны сохранять идентичность объекта
после вставки/удаления/перестановки. Массив не предоставляет непрерывный T*.

C++Builder и зависимости
Используйте Clang BCC32C/BCC32X/BCC64, не классический BCC32.
Сам nx_array_cb.h не требует эмуляции Qt. Для использования QString
нужна его реализация, предоставленная проектом; она не включена в этот
архив. Связка проверена с актуальными вспомогательными заголовками
E:\CPP10_prj\1; их хеши записаны в manifest.json. Они не изменялись.

Статус проверки
Подробности — VALIDATION.txt. Исходники используют C++11. Переносимые
версии проверены GCC в строгом C++11 на 32/64 битах. Нативные тесты Builder
выполнены в C++14 из-за constexpr-ограничений установленной Dinkumware 803.
Нативная проверка MSVC заблокирована отсутствием Windows SDK/UCRT в
настроенном окружении. Нельзя считать её заменённой проверкой GCC.
Полные приложения проектов, Qt 6 и санитайзеры не проверялись.

Тесты
В комплекте находятся исходники регрессий и Python-скрипты запуска.
Скрипты настроены на текущие локальные пути инструментов; при переносе
на другую машину скорректируйте пути Qt/Builder/Visual Studio и проекта.
Для полного набора: test_nx_qt.py, test_nx_vc.py, test_nx_cb.py.
Для целевых новых тестов: test_release_ports.py, test_qt_release_fixes.py.
После установки Windows SDK повторите test_nx_vc.py --msvc-only.
Рекомендуется полная пересборка приложений после обновления заголовков.

Состав и целостность
manifest.json содержит SHA-256 всех трёх заголовков и использованных
зависимостей Builder. Исходные проектные файлы сохранены отдельно в
каталоге original рядом с package, не перезаписаны установкой.
